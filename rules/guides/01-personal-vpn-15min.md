# 🛠 Как поднять свой непробиваемый личный VPN для Claude, ChatGPT и Gemini (Xray Reality / Каскад / XHTTP CDN / IPv6)

## Почему банят на обычных и коммерческих VPN?

Антифрод-системы **Anthropic (Claude)**, **OpenAI** и **Google Gemini** блокируют аккаунты по трем главным причинам:
1. **Грязный общий IP:** На одном сервере массового VPN сидят сотни пользователей одновременно. Достаточно одному спамеру начать регистрировать аккаунты с этого узла — под блокировку попадает вся подсеть.
2. **Прыжки по странам (Impossible Travel):** Утром автовыбор подключил вас к Финляндии, днем — к Германии, а вечером — к Турции (где **не работает Google Gemini**!). Для алгоритмов безопасности смена 3 стран за день = компрометация аккаунта.
3. **Разрывы соединения (ТСПУ / DPI):** Обычные протоколы распознаются провайдерами и рвут сессию, из-за чего клиент ИИ может отправить фоновый запрос с вашего реального IP.

### Способ 1. Голое ядро Xray (`VLESS + Reality` / `XHTTP`) и Каскадный VPN (РФ → Зарубежье)
*(Видео-разбор: [Каскадный ВПН на голом ядре X-ray](https://www.youtube.com/watch?v=1MtF_tEr4sQ))*

**Суть метода:** Минималистичная установка без тяжелых веб-панелей, не нагружающая процессор и память. Вы можете использовать один зарубежный VPS напрямую или соединить **российский VPS** (например, [Timeweb Cloud](https://timeweb.cloud/?i=138893) в Москве) с **зарубежным VPS** ([HostVDS](https://hostvds.com/?affiliate_uuid=3d2b6c0c-5d99-4065-9d37-a941a46e9282) или [is*hosting](https://ishosting.com/affiliate/ODA5NyM4) в Нидерландах). При каскадной схеме ваш провайдер видит подключение только к белому IP внутри РФ, а все нейросети видят эталонный европейский IP выходного сервера.

#### 1.1. Установка Xray на сервер в 1 команду
Подключитесь к серверу по SSH (`ssh root@ВАШ_IP`) и выполните один из авто-скриптов:

* **Вариант А — `VLESS + TCP + XTLS-Reality` (максимальная скорость):**
```bash
wget -qO- https://raw.githubusercontent.com/ServerTechnologies/simple-xray-core/refs/heads/main/xray-install | bash
```
* **Вариант Б — `VLESS + XHTTP + Reality` (разрезание пакетов против жесткого DPI):**
```bash
wget -qO- https://raw.githubusercontent.com/ServerTechnologies/simple-xray-core/refs/heads/main/xhttp-xray-install | bash
```

Скрипт сам установит свежее ядро Xray, сгенерирует ключи `x25519`, настроит маскировку (`SNI`) и выведет готовую ссылку `vless://...` + QR-код.

#### 1.2. Команды управления пользователями в терминале
После установки вы можете управлять ключами прямо в консоли сервера:
* `mainuser` — показать ссылку `vless://` и QR-код основного пользователя;
* `newuser` — создать дополнительного пользователя (например, для телефона или коллеги);
* `userlist` — вывести список всех клиентов;
* `sharelink` — сгенерировать ссылку подключения для выбранного пользователя;
* `rmuser` — удалить пользователя.

#### 1.3. Сборка каскада (Мост: Входной сервер в РФ → Выходной сервер в Европе/США)
Если прямое соединение до зарубежных подсетей ограничивается вашим оператором:
1. На **выходном зарубежном VPS** (`NL`/`DE`/`US`) установите Xray командой выше и скопируйте его `vless://` ссылку (команда `mainuser`).
2. На **входном российском VPS** (`RU`) также сначала установите базовый Xray первой командой.
3. Затем на **входном российском VPS** запустите скрипт автоматической настройки каскада (`outbound: proxy`):
```bash
wget -qO- https://raw.githubusercontent.com/ServerTechnologies/cascade-for-x-ray/refs/heads/main/cascad | bash
```
4. Вставьте в терминал скопированную `vless://` ссылку от вашего зарубежного сервера. Скрипт автоматически пересоберет `/usr/local/etc/xray/config.json` и перезапустит службу.
5. В клиент на ПК/телефоне (`Hiddify`, `v2rayN`, `Happ`, `Streisand`) добавьте ключ от **российского** сервера — весь ваш трафик прозрачно выйдет в интернет через зарубежный узел!

### Способ 2. Xray `VLESS + XHTTP` через российский CDN (Обход «белых списков»)
*(Видео-разбор: [ВПН Xray Vless XHTTP через российский CDN](https://www.youtube.com/watch?v=CMccuV5Q7AE))*

**Суть метода:** Когда мобильные операторы включают фильтрацию по «белым спискам» или режут прямые коннекты к зарубежным IP и нестандартным протоколам, трафик можно пустить через легитимный российский CDN (например, Yandex Cloud CDN с провайдером EdgeCenter).
Ваш клиент подключается по стандартному HTTPS (`443`) к узлу CDN внутри РФ, а CDN проксирует запросы на ваш зарубежный VPS. Поскольку многие CDN блокируют потоковые `POST`-запросы для не-резидентов, протокол `XHTTP` настраивается на отправку данных через метод `GET` прямо внутри HTTP-заголовков (`uplinkDataPlacement: "header"`).

#### Краткая схема развертывания:
1. **Домен и DNS:** Привяжите ваш домен к DNS-хостингу в РФ (например, Yandex Cloud DNS). Создайте `A`-запись поддомена (например, `origin.yourdomain.ru`), указывающую на IP вашего зарубежного VPS ([HostVDS](https://hostvds.com/?affiliate_uuid=3d2b6c0c-5d99-4065-9d37-a941a46e9282) / [is*hosting](https://ishosting.com/affiliate/ODA5NyM4)).
2. **Подготовка зарубежного VPS (Nginx + TLS + Xray/3x-ui):**
   * Установите Nginx и выпустите бесплатный сертификат Let's Encrypt (`certbot --nginx`) для вашего CDN-домена и origin-поддомена.
   * Установите панель `3x-ui` со свежим ядром Xray (`v26.2+`) и создайте Inbound `VLESS` на локальном порту `127.0.0.1:8080` без TLS (TLS терминирует Nginx) с транспортом `XHTTP` и путем, например, `/api/stream`.
   * В конфиге Nginx настройте проксирование этого пути в Xray с передачей пользовательского заголовка:
```nginx
location /api/stream {
    grpc_pass grpc://127.0.0.1:8080;
    proxy_pass http://127.0.0.1:8080;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header x-edge-data $http_x_edge_data;
    proxy_buffering off;
    proxy_request_buffering off;
}
```
3. **Настройка `streamSettings.xhttpSettings` (метод GET в заголовке):**
   Чтобы российский CDN не сбрасывал соединение, в настройках XHTTP задаются параметры:
   * `mode`: `"packet-up"`
   * `path`: `"/api/stream"`
   * `uplinkHTTPMethod`: `"GET"`
   * `uplinkDataPlacement`: `"header"`
   * `uplinkDataKey`: `"x-edge-data"`
   * `enableXmux`: `true` (мультиплексирование соединений)
4. **Подключение CDN:** В Yandex Cloud CDN создайте ресурс для основного домена, укажите в качестве источника `origin.yourdomain.ru` (протокол `HTTPS`) и отключите кэширование CDN. Теперь подключение идет через IP российского CDN, а выход в интернет — через ваш зарубежный VPS.

### Способ 3. Оживляем заблокированные серверы через `IPv6` и панель `3x-ui`
*(Видео-разбор: [Оживляем заблокированные серверы. Использование IPv6 для создания собственного сервера ВПН](https://www.youtube.com/watch?v=0ZHnq7V-GXA))*

**Суть метода:** Автоматизированные системы блокировок (ТСПУ) в 99% случаев блокируют конкретные `IPv4`-адреса или популярные IPv4-подсети хостингов, но **не трогают гигантское адресное пространство `IPv6` (`/64`)**. Если IPv4 вашего зарубежного VPS перестал открываться напрямую, вы можете развернуть или переключить VPN на его `IPv6`-адрес и мгновенно «оживить» сервер без смены хостинга.

#### Как настроить:
1. **Проверьте наличие IPv6 на вашем VPS:**
   На серверах [HostVDS](https://hostvds.com/?affiliate_uuid=3d2b6c0c-5d99-4065-9d37-a941a46e9282), [is*hosting](https://ishosting.com/affiliate/ODA5NyM4) и [Timeweb Cloud](https://timeweb.cloud/?i=138893) IPv6-адрес выдается бесплатно в панели управления. Проверить его на сервере можно командой:
   ```bash
   ip -6 addr show scope global
   ```
2. **Установите веб-панель `3x-ui` (если еще не установлена):**
   ```bash
   bash <(curl -Ls https://raw.githubusercontent.com/mhsanaei/3x-ui/master/install.sh)
   ```
3. **Переведите подключение на IPv6 (два варианта):**
   * **Вариант А (Если у вашего домашнего/мобильного провайдера есть IPv6):** В панели `3x-ui` создайте Inbound `VLESS + Reality`, оставьте поле `Listen IP` пустым (слушает все интерфейсы `[::]`) или укажите IPv6-адрес сервера. В клиентской ссылке замените IPv4-адрес сервера на его IPv6 в квадратных скобках: `vless://uuid@[2a01:xxxx:xxxx::1]:443?...`.
   * **Вариант Б (Если у вас дома только IPv4 — IPv6-мост):** Возьмите недорогой транзитный Dual-Stack VPS в РФ ([Timeweb Cloud](https://timeweb.cloud/?i=138893)), у которого работают и IPv4, и IPv6. Подключайтесь со своего ПК к транзитному серверу по `IPv4`, а каскад (по Способу 1) направьте с транзитного сервера на `IPv6`-адрес вашего «заблокированного» зарубежного сервера!

> 🛡️ **Важное примечание для пользователей «Заставы»:**
> «Застава» умеет отличать опасную утечку локального IPv6 провайдера РФ (`IPV6_LEAK_DETECTED` 🔴) от безопасного IPv6, который инкапсулирован внутри вашего зарубежного VPN-туннеля (`IPV6_ENCAPSULATED` 🟢). Когда вы используете зарубежный VPS с поддержкой IPv6, следите, чтобы в дашборде «Заставы» страна IPv6 совпадала со страной вашего зарубежного сервера (`NL`/`DE`/`US`).

## Шаг 3. Закрепите ваш эталонный IP в «Заставе» (1 минута)

1. Включите созданный VPN-туннель в вашем клиенте (`Hiddify`, `v2rayN`, `AmneziaVPN`, `Streisand` или `Happ`).
2. Откройте главное окно **«Заставы»** и нажмите **«Проверить сеть»**.
3. Убедитесь, что вверху отображается ваш зарубежный IP и безопасная страна (🇳🇱 `NL` / 🇩🇪 `DE` / 🇫🇮 `FI` / 🇺🇸 `US`), а все три карточки (`Claude`, `ChatGPT`, `Gemini`) горят зеленым 🟢.
4. Нажмите кнопку **«Закрепить этот IP (Pin)»** и включите **«Strict IP Pinning»**.

**Готово!** Теперь «Застава» круглосуточно контролирует ваш туннель на уровне локального прокси-сервера: если VPN-соединение случайно мигнет или переключится на другой IP, программа заморозит запросы ИИ-приложений до восстановления эталонного маршрута.
